1 · Steganography vs Encryption

Encryption

Everyone can see that a secret exists.
The content is scrambled.

"There is a locked box here."

Steganography

The secret is invisible.
It looks like a normal file.

"There is no box — just a cat photo."

The word comes from Greek: steganos (covered) + graphia (writing). The goal is not to scramble the message but to make its very existence invisible.

Real-world uses: watermarking images, covert communication, printer tracking dots (every modern printer secretly encodes serial number + timestamp on every printed page).

2 · The Least Significant Bit (LSB) technique

Every pixel in a 24-bit image is three bytes: R, G, B — each 0–255. The LSB (bit 0) of each byte contributes a value of at most 1 to the colour. Changing it is completely invisible to the human eye.

Difference: 1 out of 255 levels. The eye needs ≈ 3 levels to notice any change.

With one secret bit per carrier byte, to hide 1 secret byte you need 8 carrier bytes. For a 64×64 image (= 12,288 pixel bytes) you can hide up to 1,536 secret bytes.

4 · Decoding — recovering a secret bit

Mirror image of encoding: read the LSB of each carrier byte, shift it to the correct bit position, OR it into the recovered char.

/* recover one char from 8 consecutive carrier bytes */
c = 0;
for (b = 7; b >= 0; b--)
    c |= (px[i++] & 1) << b;     // read LSB, shift to position b
Reading LSBs of px[0..7]: 0 1 1 0 0 0 1 0

b=7: c |= 0 << 7 → 0000 0000
b=6: c |= 1 << 6 → 0100 0000
b=5: c |= 1 << 5 → 0110 0000
b=4: c |= 0 << 4 → 0110 0000
b=3: c |= 0 << 3 → 0110 0000
b=2: c |= 0 << 2 → 0110 0000
b=1: c |= 1 << 1 → 0110 0010
b=0: c |= 0 << 0 → 0110 0010 = 98 = 'b' ✓

Tip — using nibbles instead of bits: you could hide the full low nibble of each carrier byte (4 bits per byte instead of 1). Capacity × 4, but the colour changes by up to 15 instead of 1 — potentially visible on solid-colour regions.

6 · Why JPEG is a bad carrier

JPEG is a lossy, compressed format. It does not store raw pixel bytes — it stores DCT (Discrete Cosine Transform) coefficients, Huffman-coded. When you modify the LSBs of a JPEG file you are modifying compressed bitstream data, not pixel colours. Re-saving or re-encoding the image will completely destroy any hidden data.
FormatStorageLSB steganography
BMP Raw pixel bytes, uncompressed ✓ Perfect — bytes stay intact
PNG Lossless compressed (deflate) △ Works on raw data only (decompress → modify → recompress)
JPEG Lossy compressed (DCT + Huffman) ✗ Re-encoding destroys hidden data
Any file — Raw bytes can always be used if the file is never re-encoded

7 · BMP — the right format for this demo

BMP stores pixel bytes directly after a 54-byte header. No compression. What you write is what you read back.

BMP file layout (24-bit, no palette):

┌─────────────────┬──────────────────────────────────────────────────────┐
│ File header │ DIB header (BITMAPINFOHEADER) │
│ 14 bytes │ 40 bytes │
├─────────────────┴──────────────────────────────────────────────────────┤
│ Pixel data — raw BGR bytes, rows stored bottom-up │
│ width × height × 3 bytes (rows padded to multiple of 4) │
└────────────────────────────────────────────────────────────────────────┘

Pixel data starts at byte offset 54. Embed your secret starting there.

8 · The demo program — stego.c

The program stego.c in this folder:

  1. Builds a 64×64 BMP cat face image in memory
  2. Embeds "bounjour monde, guilhmar is on its eye" into the pixel LSBs
  3. Saves cat_stego.bmp — open it to see a normal cat
  4. Decodes the hidden message and verifies it matches

Hints — key operations in the code (no full functions)

/* ── embed: for each bit of the secret string ── */
// iterate i = 0 to (strlen(SECRET) + 1) * 8 - 1  (+1 for '\0')
// extract bit at position i from the secret:
bit = (SECRET[i / 8] >> (7 - i % 8)) & 1;  // which char, which bit (MSB first)
// write that bit into the LSB of the carrier:
px[i] = (px[i] & 0xFE) | bit;            // clear LSB → set to secret bit

/* ── decode: for each recovered char ── */
// read 8 pixel LSBs, assemble them into one char (MSB first)
c = 0;
for (b = 7; b >= 0; b--)
    c |= (px[i++] & 1) << b;
// stop when c == 0 (null terminator recovered)

/* ── capacity check ── */
need_bits = (strlen(SECRET) + 1) * 8;
// must be ≤ PIXSZ  (image width × height × bytes_per_pixel)
Connection to nibbles (ex11/ex12): the operations are identical — >> n to extract a bit, & 1 to isolate it, & 0xFE to clear the slot, | bit to write it. Steganography is just nibble-extraction applied to 1-bit slices instead of 4-bit slices.
